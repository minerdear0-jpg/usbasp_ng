## Optiboot — не мешать с oracle на одном образе

hfuse 0xC4, 512 B boot, BOOTRST → boot section **0x1E00–0x1FFF**.

Канарейка oracle сидит ровно там. Намеренно: last-page flush ISP.
С Optiboot на том же чипе:

  1. ISP `make flash` oracle     — затирает Optiboot канарейкой
  2. `flash-uart`                — boot не пишется, канарейка не
                                   попадает / остаётся код бута → CANARY FAIL
  3. EESAVE в 0xC4               — chip-erase не трёт EEPROM,
                                   мой eeprom=chip_erased молчит

Итог: **два режима, не один hex.**

  nano-loop + bootloader + flash-uart  — повседневный UART, Optiboot жив
  oracle + ISP (harness.py run)        — приёмка diagplane, хвост flash наш

Не жги `make bootloader` на чип, который сейчас oracle, и наоборот
не `make -C bench/mega8-diag-oracle flash`, если хочешь сохранить бут.
YEL0 как recovery — ок.

Если понадобится oracle *поверх* Optiboot: сдвину канарейку на 0x1C00
(512 Б перед boot). Для ISP-приёмки MEMOP last page я бы этого не делал.

Fuses на твоей Nano после первого `bootloader` — пришли lfuse/hfuse/lock
как измерите. 16 МГц я не трогал (F_CPU=16000000, как loop).
